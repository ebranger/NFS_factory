Compiling NFS_factory
=====================

The code is compiled with Visual Studio on 64-bit Windows, and the project files are included. It requires the MPIR library (a Windows-friendly fork of GMP), which has to be built separately.

There are two solutions, for Visual Studio 2026 (platform toolset v145), x64 only:

  NFS_factory_VS2026.sln   The CPU build, NFS_factory.exe. The steps below describe how to set it up.
  NFS_factory_GPU.sln      The GPU build, NFS_factory_gpu.exe, which also needs the CUDA Toolkit (see section 5).

Both build the same source files in the NFS_factory and int_ntt folders, the GPU build also the .cu files.


1. Install the tools
--------------------

- Visual Studio 2026 (Community edition is fine) with the "Desktop development with C++" workload.
- Python 3, only needed to run the MPIR tests (optional).
- The YASM assembler 1.3.0, needed to build MPIR's assembly code, from https://github.com/yasm/yasm/releases/tag/v1.3.0
  Download vsyasm-1.3.0-win64.zip and yasm-1.3.0-win64.exe. Create the folder C:\Program Files\yasm and place
  in it the files from the zip (vsyasm.exe, vsyasm.props, vsyasm.targets, vsyasm.xml) and yasm-1.3.0-win64.exe
  renamed to yasm.exe.
  Alternatively, keep them in another folder and set the environment variable YASM_PATH to that folder
  (including a trailing backslash).


2. Build MPIR
-------------

MPIR is no longer developed, but Brian Gladman maintains its Windows build files, including for Visual Studio 2026:
https://github.com/BrianGladman/mpir

Download or clone it, open mpir\msvc\vs26\mpir.sln in Visual Studio, and build these projects for x64:

  lib_mpir_skylake_avx   the MPIR library with assembly code for modern Intel and AMD processors (with AVX2).
                         Use lib_mpir_gc instead on older processors. It needs no YASM, but is much slower.
  lib_mpir_cxx           the C++ interface (mpirxx).

Build both in the Release configuration, and also in Debug if you want to debug NFS_factory.
The build copies the results to mpir\lib\x64\Release and mpir\lib\x64\Debug.

Optionally, run the MPIR tests: build mpir\msvc\vs26\mpir-tests.sln and run run-tests.py in the same folder.
At the time of writing, two things in the MPIR test setup need working around:
- In the vs26 test projects, the pre-build step calls "check_config $(Platform) $(Configuration) 22";
  change 22 to 26 in the test .vcxproj files.
- Build the add-test-lib project first, since a parallel build may try to link the tests before it is ready.


3. Copy MPIR into this project
------------------------------

Copy the files into the third_party\mpir folder next to NFS_factory_VS2026.sln, so that it looks like this:

  third_party\mpir\include\mpir.h
  third_party\mpir\include\mpirxx.h
  third_party\mpir\lib\x64\Release\mpir.lib
  third_party\mpir\lib\x64\Release\mpirxx.lib
  third_party\mpir\lib\x64\Debug\mpir.lib       (only needed for Debug builds)
  third_party\mpir\lib\x64\Debug\mpirxx.lib     (only needed for Debug builds)

The headers are in mpir\lib\x64\Release, and are the same for Release and Debug. The .pdb files may be copied
too, for debugging into MPIR. Another location can be used by changing the MpirDir macro in
NFS_factory\NFS_factory_VS2026.vcxproj.

The MPIR libraries are built with the static runtime library (/MT, or /MTd for Debug), and the project is set up
to match. Mixing the two gives linker warning LNK4098, and a slower or broken program.


4. Build NFS_factory
--------------------

Open NFS_factory_VS2026.sln, select Release and x64, and build. The program ends up in x64\Release\NFS_factory.exe.

Run it as:
  NFS_factory <polynomial file name> <saved relation file name> <output file name>


5. The GPU build (optional)
---------------------------

NFS_factory_GPU.sln builds NFS_factory_gpu.exe, which does the product and remainder trees on an NVIDIA GPU. It
needs the CUDA Toolkit 13.4 (with its Visual Studio integration, which the CUDA installer adds) and builds the same
source files as the CPU build, plus the .cu files, with NFS_GPU defined. The project builds code for compute
capabilities 7.5, 8.0, 8.6, 8.9, 9.0 and 12.0 (RTX 20 series to RTX 50 series, and the data center GPUs of those
generations), and PTX for 12.0, which newer GPUs compile when the program starts. To build for fewer GPUs, which is
faster, edit CodeGeneration in NFS_factory\NFS_factory_GPU.vcxproj. CUDA 13 supports compute capability 7.5 and
later. Another CUDA version needs the "CUDA 13.4" props and targets imports there changed to that version.

The CPU build needs no CUDA. Both builds take the same polynomial and relation files and write the same relations.

6. Linux
--------

The Makefile in the main folder builds both programs with GCC and MPIR. Linux/include/intrin.h stands in for the intrinsics of
Visual Studio. MPIR is built from its sources (https://github.com/wbhart/mpir), with YASM and the autotools:

  apt install build-essential yasm autoconf automake libtool texinfo
  git clone https://github.com/wbhart/mpir && cd mpir
  ./autogen.sh
  ./configure --prefix=/opt/mpir --enable-cxx
  make && make install

MPIR's configure picks the assembly code for the processor, but does not know many newer ones, and then builds its generic
x86_64 code (./config.guess shows x86_64-unknown-linux-gnu).
Then --build=skylakeavx-pc-linux-gnu selects the code of lib_mpir_skylake_avx (for processors with AVX2).
MPIR's sources are old enough that GCC 15 may not build them; CC=gcc-13 CXX=g++-13 before ./configure sets another compiler.

Then, in the main folder of NFS_factory:

  make                 the CPU build, build/NFS_factory, and the utilities
  make gpu             the GPU build, build/NFS_factory_gpu, which needs the CUDA Toolkit (nvcc)
  make utils           only the utilities of the Utilities folder, build/RelationsToBinaryFormat and build/RelationFilterSplit
  make both            all of them

RelationFilterSplit.cpp is saved as UTF-16, which GCC does not read; the Makefile compiles a UTF-8 copy that iconv (part of
the C library tools on Linux) writes to build/utils.

MPIR is linked statically. MPIR_DIR=<folder> sets where MPIR is installed (default /opt/mpir). The GPU build compiles for the GPUs
of the machine (CUDA_ARCH=native); CUDA_ARCH="75 86 120" builds for others. nvcc needs a host compiler that its CUDA version
supports, set with NVCC_CCBIN, for example make gpu NVCC_CCBIN=g++-13 for CUDA 12.4.
